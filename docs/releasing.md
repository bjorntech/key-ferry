# Release checklist

This is a manual maintainer process. No release, tag, push, or publication is
performed automatically by this document.

## Verify the package

From the repository root, run the existing checks in this order:

```sh
bun install --frozen-lockfile
bun run format:check
bun typecheck
bun test
bun run test:coverage
bun run test:crap
bun run build
bun pm pack --dry-run
```

The coverage gate requires aggregate runtime-source coverage of at least 90%
for lines and 75% for functions. The CRAP gate requires new or changed
functions to score at most 6; unchanged legacy violations warn, while
regressions against the committed baseline fail. Review both reports rather
than treating a warning as proof that the whole repository passes CRAP.

Run the two opt-in Varlock integration fixtures separately with a configured
CLI path and synthetic isolated fixtures:

```sh
VARLOCK_LIVE_BINARY=/absolute/path/to/varlock bun test tests/varlock-live.test.ts
VARLOCK_LIVE_BINARY=/absolute/path/to/varlock bun test tests/remote-varlock-live.test.ts
```

These fixtures do not substitute for production deployment or compatibility
testing with every external MCP service.

## Review and publish manually

Before release, verify the package version, changelog, exports, generated
package contents, npm public-scope permissions, and intended repository
visibility. Review the release commit, then make the commit, push the selected
branch, and create and push the matching version tag only after the maintainer
has explicitly approved those actions.

Publish the package manually using the maintainer's npm process, with public
scoped access and npm provenance when required by that process. Verify a clean
registry installation and the documented OpenCode V2 plugin/TUI discovery path
after publication. There is no autogenerated tag or publish workflow.
